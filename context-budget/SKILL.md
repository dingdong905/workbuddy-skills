# Context Budget（上下文预算审计）

产出只读的、基于证据的上下文审计报告。先优化信息路径，再缩短任务关键指令。

## 盘点范围

只检查实际存在且相关的部分：

- 记忆层：`~/.workbuddy/MEMORY.md`（用户级）、项目 `.workbuddy/memory/MEMORY.md` 与每日日志、云端注入的 profile 摘要
- 已安装 skills：`~/.workbuddy/skills/`（用户级）与项目 `.workbuddy/skills/`；区分常驻元数据（name + description）与按需加载的正文、references
- MCP 服务器与插件：`~/.workbuddy/mcp.json` 中配置的服务器、已连接 connector 暴露的工具 schema
- 重复内容：跨记忆层、跨 skill、跨项目文档重复的规则、模板、事实
- 检索行为：整文件读取、重复搜索、重复来源、超大工具输出

WorkBuddy 的 skills 采用渐进式加载：元数据常驻上下文，SKILL.md 正文与 references 触发后才加载。不要把所有已安装 skill 的正文都算作常驻开销。

## 度量（拒绝虚假精度）

有可用 tokenizer 就用；否则用一致近似并标注"估算"：英文/代码类文本按字符数除以四，中文按每字 1.5–2 token 估算，结构化 schema 可能显著更高。

分开统计：

- 常驻项：系统注入的指令、工具 schema、skills 元数据、云端 profile
- 条件加载项：skill 正文与 references
- 任务项：会话中检索的内容与对话历史
- 持久项：各层记忆文件

报告数量、估算 token、重叠度、触发面广度和置信度。不要臆测上下文窗口大小、缓存行为或单个工具的开销。

## 诊断

把组件分为四类：

- **保留**：高频使用、唯一、精炼
- **懒加载**：有用但限定领域或阶段——考虑移入 references 按需加载
- **合并**：实质重复的指引或内容
- **退役候选**：过时、未用、不兼容或已被完全取代

重点标记：

- 触发词过宽的 skill description（会被无关任务激活）
- 用户级与项目级记忆中的重复规则
- 只用一两个操作却暴露大量工具的 MCP 服务器
- 未做相关性过滤就读取整个文档/仓库
- 已总结过的原始工具输出仍留在上下文中
- 同一事实同时存在于云端记忆、用户级 MEMORY.md 和项目日志中
- 没有标注 as-of 日期的时效性记忆

## 按影响力排序优化

1. 停用不用的 MCP/工具面；当前操作优先用专用 connector 或 CLI
2. 收窄 skill 的 description 与 triggers，合并重叠 skill，保留独有工作流
3. 记忆文件保持精简；条件性细节移入对应 skill 的 references
4. 渐进检索：先搜元数据/片段，排相关性，再深读决定性文件
5. 在逻辑边界（阶段完成、长任务切换）用紧凑的阶段摘要、证据台账或交接说明替换大段原始历史
6. 跨记忆层去重稳定事实
7. 结构性浪费清除后，才着手精简措辞。保留安全、正确性、来源与授权约束

## 记忆落位（WorkBuddy 三层）

- 云端记忆（profile）：服务器维护，只读，不要本地覆写
- `~/.workbuddy/MEMORY.md`：跨项目的用户级长期规则与偏好
- 项目 `.workbuddy/memory/MEMORY.md`：本项目长期事实与约定；`YYYY-MM-DD.md` 每日日志只追加
- 任务台账 / 交接说明：临时状态，必须有 as-of 日期和明确的过期或关闭条件

不要把一次性纠正、未验证断言、密钥凭据或敏感个人信息升格为持久记忆。写入或修改任何持久上下文前先征得用户同意。

## 输出

报告开头给出估算总开销和三项最高价值的改动。随后是紧凑的分类明细、每项发现的证据、预期节省区间、质量风险、可回滚的行动方案。

审计默认只读。除非用户明确要求，不删除 skill、不停用连接器、不改配置、不重写记忆。用户批准变更后，用同样的组件重新度量并报告实测差值。
