# 输出长度纪律（防截断）

单次回复超过模型 max token 限制会被强制截断，尾部内容丢失，用户被迫"继续对话"才能拿到残缺的下半段。本 skill 从源头控制单次输出规模。

## 第一条：先估后写

动笔前粗估输出规模（中文 1 字约 1.5–2 token），按档处置：

| 预估规模 | 处置 |
|---|---|
| ≤800 字 | 直接回复 |
| 800–2000 字 | 先压缩（见压缩手法），再回复 |
| >2000 字，或 >100 行代码，或多个文件/多张表 | 写文件 + present_files，对话只给 ≤300 字摘要与关键结论 |

## 硬性上限

- 对话正文默认 ≤1500 字；成型后自查，感觉接近上限立即砍
- 对话内不贴 >100 行代码，代码一律写文件
- 砍的优先级：次要示例 > 重复解释 > 修饰词；结论、行动项、命令永远保住

## 分块交付（内容必须留在对话里时）

- 按逻辑单元拆块，每块独立可读、可粘贴
- 先给第一块，块尾标注"共 N 块，要继续吗"
- 绝不一口气全吐——宁可多一轮交互，不要赌一次输出

## 工具调用纪律（截断的另一来源）

截断不只发生在回复正文，也发生在单次工具调用的输出：一次性读多台机器全量文件、贴大段命令输出后附带长分析，单轮 token 同样爆。规则：

- 多机器/多文件收集，一次只处理一个目标，分多轮调用
- 读大文件先 Read offset/limit 分段，或先 grep 定位再精读
- 命令输出先过滤（grep/wc/head），只取关键行，不整段回贴
- 拿到一批数据就先给结论，不要攒到最后一次性大输出
- 高危操作例外（如备份、变更）允许较长输出，事后仍需摘要

## 压缩手法（降字数不降信息）

- 表格替代重复段落；同维度信息合并成对照表
- 结论先行：核心判断 → 展开 → 细节，读者随时可停
- 不复述用户已知上下文、刚贴过的命令输出、上一轮已给过的内容
- 删寒暄、删"以下是"、删"值得注意的是"、删总结性废话
- 代码只给 diff 或关键段，全量进文件

## 长任务

多步骤任务每步只报一句话进度 + 关键结果；最终汇总 ≤500 字 + 交付文件。过程细节写进日志或文件，不在对话里直播。

## 例外

用户明确要求"完整输出 / 全部内容 / 不要省略"时，仍然写文件承载全文，对话给结构化摘要（章节目录 + 每节一句话）——而不是在对话里赌一次超长输出。

## 自查清单（回复发出前）

1. 预计字数是否 ≤1500？超过 → 压缩或转文件
2. 有没有贴大段代码/原始输出？有 → 转文件
3. 是否重复了任何已知信息？有 → 删
4. 如果这条回复被截断，丢的会是结论还是废话？废话 → 重排，结论前置
