# Evidence Research（证据研究）

构建一个其他分析师可审计的答案。优化目标：决策价值、来源质量、边际信息增量——不是收集链接数量。

## 定框架

- 先说明决策或问题、范围、辖区和 as-of 日期
- 把宽问题拆成 3–6 个子问题；识别哪些断言会改变结论
- 请求明确时用合理默认值；只有缺失的选择会实质改变结果时才提问

## 工具与来源路由

浏览器操作前，先检查有没有专用 connector、本地源、API 或 CLI 能完成该语义操作。WorkBuddy 环境常用映射：

- 实时性/新闻类信息：网页搜索
- 定向抓取已知 URL：网页抓取（重定向时跟踪新地址）
- 金融/投资类深度多源检索：`agentic_search`（成本高、延迟大，仅用于需要多源交叉验证的复杂金融调研；简单查询不要用它）
- 历史会话与既往结论：`conversation_search`（查询必须自包含，它看不到当前对话）
- 已连接的 MCP connector：邮件、文档、表格等领域专用工具

只用真实存在的工具；绝不发明 connector 或命令。

证据分级：

1. **一手**：监管/政府记录、交易所披露、公司公告、标准、法院记录、原始数据集、源代码、原始研究
2. **第一方佐证**：投资者关系材料、技术文档、业绩说明会、官方公告
3. **独立二手分析**：方法透明的研报与评估
4. **聚合器**：新闻摘要、博客、论坛、社媒——只作为线索或情绪证据，不作为事实依据

关键断言优先"一手来源 + 一个独立交叉验证"。只有一个来源时，明确标注"未验证"。

## 渐进检索

1. 构建小查询组合：精确词、同义词/缩写、中文变体、时间限定、反证查询
2. 先扫标题、摘要、元数据、目录；对镜像、转载、引用同一上游的来源去重
3. 只深读最可能决定问题的 3–5 个来源；证据冲突或关键缺口仍在时才扩展
4. 每个有用来源记录：标题、发布方、日期、URL 或文件位置、相关章节/页码、支持的断言、局限性
5. 评估缺口并调整查询；除非用户明确要求穷尽覆盖，最多三轮精化

停止条件：新来源大多在重复已知事实；所有承重断言证据充分；矛盾已解决或已明确划界；剩余不确定性不会改变决策。陈述未解决的缺口，而不是无限搜索。

## 综合前先分析

- 区分：有源事实 / 计算 / 推断 / 预测 / 观点
- 比较数字前，先对齐冲突的日期、单位、定义、合并/母公司口径与修订
- 时效门槛：确认已纳入的最新报告期，再搜索可能推翻它的后续事件
- 主动找最强可信反证，并说明它是否改变结论
- 证据分级为 高 / 中 / 低，依据：来源层级、直接性、跨源一致性、时效性、方法透明度
- 不把"没找到证据"当作"证据不存在"

## 面向决策综合

开头直接给答案和置信度。随后：

- 决定结论的关键发现
- 紧邻每个关键断言的证据与引用
- 矛盾、未知、假设
- 最强的替代解释
- 什么未来证据会证实或证伪结论
- 大型研究附精简来源列表与方法说明

重复对比才用表格。用户要求持久产物或内容放不下时，才把证据台账或完整报告存为文件。

## 金融场景路由（WorkBuddy 环境实际可用）

- 行情、财报、估值、板块等金融数据与场景：先经 **wb-finance-skill** 总入口
- 个股波段判断、仓位节奏、预期差分析：**growth-swing-trading** 出判断框架，本技能负责文档获取与交叉验证
- 本技能不替代上面两者，也不虚构不存在的技能；环境里没有的能力，如实说明并给出替代路径
- 严禁混用报告期、单位、币种、口径。每个财务数字标注来源与报告期；现价与市值标注 as-of 时间戳

## Token 与记忆纪律

- 先取元数据和摘录，再取全文；避免加载重复页面或整个仓库
- 每深读一个来源，先总结成断言与证据，再开下一个
- 携带紧凑证据台账，而非原始抓取输出
- 只加载与当前模式相关的 references；已准确捕获的内容不重复转述
- 时效性事实视作会过期。用户要求或属稳定项目规则时才落持久记忆：偏好进用户级 MEMORY.md，项目规则进项目 memory/MEMORY.md
- 绝不把密钥、凭据、敏感财务数据、未验证断言存为记忆

## 失败条件

访问受阻、来源付费墙、数据过期、一手记录不可得时，不声称"已全面覆盖"。报告缺口、其可能影响、以及下一步需要的确切文档或权限。
